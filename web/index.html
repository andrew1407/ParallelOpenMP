Parallel OpenMP Labs

The ParallelOpenMP labs, running in your browser. Their C++ is compiled to WebAssembly, and each OpenMP thread or MPI rank is a Web Worker.

How the threads run here

Native OpenMP needs threads that share memory. In WebAssembly that means emscripten pthreads, which need SharedArrayBuffer, which browsers only allow on cross-origin-isolated pages (the COOP/COEP headers). GitHub Pages can't send those headers. coi-serviceworker can add them, but it has to reload the page on the first visit and doesn't work in every browser. Even with pthreads, emscripten has no OpenMP runtime (libomp) for the pragmas. So this page does what the OpenMP runtime would do, by hand:

  • The lab sources compile without -fopenmp, so the pragmas are ignored, against a small omp.h that provides omp_get_wtime(), omp_get_thread_num() and the rest.
  • A parallel region is a fork over N Web Workers, each running the same WebAssembly module. Each worker gets the thread number and the share of the loop or task tree that OpenMP would give that thread (the default static schedule, the same chunking as the lab). The join is waiting for every reply, and reductions and atomic updates are added up from the replies.
  • Workers don't share memory, so the inputs a thread needs are rebuilt in each worker (the same seed) or sent along, and the results come back as copies. That cost is included in the wall-clock times, measured on the page from fork to join.
  • #pragma omp simd (labs 5–6) doesn't use threads. -fopenmp-simd makes clang honour it without a runtime, and -msimd128 lets it use WebAssembly SIMD.
  • MPI (lab 7): each rank is a worker running the lab's main(). MPI_Send posts the buffer through the page to the other rank, and a blocking MPI_Recv waits for it with Asyncify.
Timings are measured in your browser, and vary between runs and machines. Browsers round timers to about 0.1 ms on pages without cross-origin isolation. DichES
